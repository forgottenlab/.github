# 🤝 Contributing / 贡献指南

[Engineering handbook](docs/standards/README.md) · [工程手册](docs/standards/README.zh-CN.md) · [Licensing](docs/standards/LICENSING.md) · [许可证规范](docs/standards/LICENSING.zh-CN.md)

维护者的低风险改动可以直接提交到 `main`。较大变更和外部贡献再使用 Pull Request。不要求独立审查者。

Low-risk maintainer changes can go directly to `main`. Use a pull request for a substantial change or an external contribution. No independent reviewer is required.

Issue 使用描述性标题，不加 `[Bug]`、`bug:` 这类前缀。按需选用缺陷、功能、任务或测试与验证表单。标签保持很少。

Use a descriptive issue title, without a `[Bug]` or `bug:` prefix. Choose the Bug, Feature, Task, or Test & Validation form when it fits. Keep labels few.

缺陷证据优先附在原缺陷 Issue。任务的验证结果可以写在原 Task 或 PR；独立测试可用测试与验证表单。公开上传附件前请先脱敏。

Attach bug evidence to the original Bug issue. Record task verification in the original Task or PR. Use Test & Validation for standalone tests. Remove sensitive information from public attachments before uploading.

不要提交密钥、令牌或本地配置。

Do not commit secrets, tokens, or local configuration.

维护者的 Issue 和 PR 标题与正文采用项目维护交流语言。维护者撰写中文 Issue 时，在正文末尾附简短的 **English Summary**。中文 PR 的英文摘要按需添加。语言选择的优先级见工程手册。

Maintainers use the project's maintenance language for issue and PR titles and bodies. End maintainer-written Chinese issues with a brief **English Summary**. Add an English summary to Chinese PRs when it helps readers. See the engineering handbook for how to choose the language.

外部贡献者可用英文或简体中文提交 Issue 和 PR，英文摘要可选。全文翻译对所有人都是可选的。

External contributors can use English or Simplified Chinese for issues and PRs, with an optional English summary. Full translations are optional for everyone.
